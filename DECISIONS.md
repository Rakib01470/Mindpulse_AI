# MindPulse AI — Decisions Log

Where DEVELOPMENT_PLAN.md was ambiguous, contradictory, or no longer workable, the simplest option consistent with Section 2 (Assumptions) was chosen and recorded here.

| ID | Phase | Topic | Plan said | Decision | Why |
|---|---|---|---|---|---|
| D-01 | 1 | AI model | `claude-3-5-haiku-20241022` | Default model is `claude-haiku-5-5`, set once in `src/utils/constants.ts` (`AI_MODEL`). | Anthropic retired claude-3-5-haiku-20241022 on 19 Feb 2026; every request to it now fails. The official replacement (`claude-haiku-4-5-20251001`) is only guaranteed until 15 Oct 2026. Haiku 5.5 keeps the plan's intent (fast, cheap Haiku tier). |
| D-02 | 1 | Voice in Expo Go | expo-speech-recognition **and** "Expo Go compatibility" | Keep expo-speech-recognition (Section 2 #3). It is a custom native module, so dictation needs a **development build** (`eas build --profile development` or the preview APK). The module is loaded lazily; in Expo Go the voice overlay shows a notice and a text box so the full AI-parsing flow still works by typing. | The two requirements cannot both hold — expo-speech-recognition is not bundled in Expo Go. Section 2 wins over the tooling note; nothing crashes in Expo Go. |
| D-03 | 1 | expo-sqlite version | v14.x | `~15.1` (the version bundled with Expo SDK 52). Same async API. | v14 belongs to SDK 51; SDK 52 / Expo Go 52 ship 15.x natively, and mixing versions breaks the native module. |
| D-04 | 1 | Library versions | lucide-react-native, React Navigation v7 (unpinned) | lucide-react-native pinned to `0.460.0` (SDK 52-era, plain JS entry); React Navigation `^7`. | The newest lucide ships `.mjs` entry points that SDK 52's Metro does not resolve by default. |
| D-05 | 1 | Screens folder | Section 7 has no screens directory | Added `src/screens/` for the 5 tab screens plus TaskDetail, ProjectDetail, NoteEditor and VoiceCapture. | Screens need a home; components/ stays for reusable pieces as specified. |
| D-06 | 1 | Extra Expo modules | — | Added `expo-sharing` (Android share sheet), `expo-document-picker` (backup file picker), `expo-crypto` + `expo-secure-store` (API key encryption), `@react-native-community/datetimepicker` (due date/time), `@react-native-community/slider` (progress slider). All are Expo SDK 52 modules supported in Expo Go. `expo-asset`, `expo-font`, `@expo/vector-icons`, `expo-constants` installed explicitly because Metro could not resolve them transitively. | F2/F6 call for a slider, share dialog and file picker; none of these are custom native code. |
| D-07 | 1 | Theme mapping | Token `primary` = `#1E293B` | Paper's interactive `primary` colour uses token `accent` (`#0EA5E9`). Token values are kept verbatim in `ThemeTokens`. | `#1E293B` equals the card surface colour — buttons and FABs would be invisible on cards. |
| D-08 | 2 | "Encrypted" API key in SQLite | Encrypted input saved in the settings table | A random 32-byte master key is created once and kept in `expo-secure-store` (Android Keystore). The API key is encrypted with it (SHA-256 counter-mode keystream + 128-bit integrity tag, `src/utils/keyCipher.ts`) and only the ciphertext is stored in `settings`. JSON backups never include settings or the key. | Satisfies "encrypted" and "settings SQLite table" with no extra native module; expo-crypto has hashing but no AES. |
| D-09 | 2 | Conflicting message texts | F1/F6 and Section 10 give different wording for the same events | Feature-spec wording wins: network loss during parsing → "Network unavailable. Saved raw voice input to Task Title for manual editing."; bad backup → "Invalid backup file format. Operation cancelled."; key test → "Valid Key" / "Invalid Key". All strings live in `MESSAGES` in `constants.ts`. | Acceptance criteria are more specific than the catalogue. |
| D-10 | 2 | Low-priority badge colour | F2 says Grey; token `priorityLow` is Emerald Green | Badge uses grey (`textMuted`) per F2. | F2 describes the badge explicitly. |
| D-11 | 2 | AI failure behaviour | "falls back to manual entry form" and "creates task locally" | No key / invalid key / unparseable reply → review card pre-filled with the raw transcript as title (user taps Save). Network failure → task is created immediately with the transcript as title and default fields, then the banner and Edit Task / Done buttons are shown. | Matches each acceptance criterion literally without adding steps. |
| D-12 | 2 | Offline speech | "100% offline & free" | Recognizer is started with `EXTRA_PREFER_OFFLINE`, so Android uses the on-device model when the language pack is installed; otherwise Android's recognizer may use the network. Language is `en-US`. | Android does not guarantee offline recognition for every device/language; forcing `requiresOnDeviceRecognition` would fail outright on phones without the pack. |
| D-13 | 2 | Voice flow | "When speech stops or user taps Stop & Process" | Overlay is a full-screen modal route. Recognition runs in single-utterance mode and processing starts automatically when Android detects end of speech (2 s pause); "Stop & Process" ends early. A JS timer aborts after 5 s with no speech. The transcript is editable before processing. | Direct reading of F1 + Section 10. |
| D-14 | 3 | Progress "real-time" | Slider updates progress_percent in real time | The % label and slider move live while dragging; the value is written to SQLite when the finger lifts (optimistic UI update first). Slider steps by 5%. Status follows progress: 0 → Pending, 1–99 → In Progress, 100 → Completed. | Writing on every drag frame would flood SQLite; the user sees no difference. |
| D-15 | 3 | Checkbox semantics | Checkbox marks Completed | Checking sets Completed + 100%. Un-checking re-opens the task as Pending at 0%. | Keeps status and progress consistent for the 100% auto-complete rule. |
| D-16 | 3 | Where categories are managed | "+ Add Category" on Task List; delete prompt | "+ Add Category" chip on the Tasks screen and a button in Settings. Delete via long-press on a custom chip or the trash icon in Settings, both with the exact F2 prompt. Office Work / Personal Work are locked. Tasks are moved to Personal Work in the same transaction (the schema's ON DELETE CASCADE never fires). | Settings is listed in Section 6 as managing custom categories. |
| D-17 | 3 | Manual task entry | Not specified beyond voice fallback | Small "+" FAB above the mic FAB opens the same form. | Needed for typing a task without voice, and for Expo Go. |
| D-18 | 4 | Timer mechanics | Live stopwatch that survives navigation; "background duration calculation" | Timer state is timestamps (`runningSince`, `accumulatedMs`), not a counter, and is saved to `settings.active_timer` on every change. It keeps correct time across tabs, backgrounding and app restarts. While the Stop dialog is open the timer is paused, so time spent typing notes is not counted. | Simplest design that is accurate without a background task. |
| D-19 | 4 | Second timer | "automatically pauses/prompts to save Project A" | Starting B while A exists shows the exact Section 10 message with **Cancel** / **Save & start B** (A is saved without notes, then B starts). | Only one timer may exist, so A cannot stay paused while B runs. |
| D-20 | 4 | Default target hours | Schema default 100.0, entity table default 50.0 | New-project form defaults to 50 hrs; the schema default is left as written. | The entity table describes app behaviour. |
| D-21 | 4 | Extras | — | Sessions under 1 s are not logged. Session logs can be deleted (long-press), subtracting the time. Manual entries are capped at 744 h per entry and logged as ending now with note "Manual entry". Project cards show live hours while the timer runs. | Small guards for typos and mis-taps. |
